Decisions on this hero
The token is timed to the footage, not to a timer. A timeupdate listener opens a 1.35s window at a fraction of the clip's duration (default 45% — currently 2.29s–3.64s of a 5.08s clip), so it tracks the handoff whatever the cut length. It never shows on the first or last frame. The current asset is a placeholder, and it fights the system. The clip is saturated cartoon artwork containing the exact things the brief rules out — currency coins, stars, percentage badges, an app screen in the footage — so no grade will reconcile it with #F5F7F8 / #2B5748, and the pale-yellow token cannot read against the yellow coins already in frame. Swap the file at uploads/ for the barista clip and re-set the two Tweaks sliders onto the cup; nothing else needs changing. One motion event, three parts. A soft pulse at the cup, one token rising 40px and fading, and a smaller delayed pulse near the receiving hand. Nothing else on the page moves — headline, CTAs and copy are static by choice. No frame, and no UI added by me. The video sits in an 18px-radius container with a 1px hairline and the resting shadow only — no laptop, phone or browser chrome, and nothing I overlay pretends to be an app. Grade is a light saturate(.93), which is right for real café footage; the placeholder clip needs far more correction than that, which is a reason to replace it rather than grade it. Alignment is a tweak, not a guess. Token X/Y, hand-pulse X/Y, the reward moment and the optional "Loyalty reward" pill are all props — the pill is off by default, because the rising token reads without a label. Mobile stacks copy first, video last in a 4:5 crop with object-fit:cover, and the token sits at the same relative position so it can't be cropped away. Reduced motion freezes every animation and leaves the footage as a still.
