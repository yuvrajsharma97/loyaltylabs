00

Assumptions & reasoning

Assumption 01

Two users, one language. The customer wallet is consumer-grade and one-handed; the shop-owner console is high-throughput. Same tokens, same components — density and nav change, not the visual language.

Assumption 02

Olive carries action, orange carries attention. Every primary CTA is olive. Orange is reserved for progress toward a reward, unread state, and "ready to redeem" — so it always means something is available to you.

Assumption 03

Fresh token layer, existing role names. Your tokens.css already keys off Material-style roles that every component consumes. I keep the role names and replace the values, so this palette lands without touching component code.

Assumption 04

Borders over shadows. One 1px border colour and two elevation levels total. Elevation is reserved for things that genuinely float: sheets, toasts, dropdowns. Cards sit flat on ivory.

03b

Glass — chrome and overlays only

Glass earns its place on the layers that float over content: the app bar, the bottom nav, sheets and dialogs, and status pills sitting on imagery. It never touches a surface carrying money — a balance, an amount, a transaction row — because translucency costs contrast and contrast is what makes figures scannable. Blur is depth, not decoration: if nothing scrolls behind an element, it isn't glass, it's a tinted panel.

App bar
navnavnav
Chrome rgba(245,247,248,.72) · blur 18 · saturate 140% App bar, bottom nav, sticky headers. 1px #E1E6E8 edge; content scrolls behind.
Confirm redemption
Overlay rgba(255,255,255,.86) · blur 28 · scrim blur 3 Sheets and dialogs. High opacity, because these hold the confirmation ledger.
Subscribed
Pill on imagery rgba(255,255,255,.62) · blur 10 Status over a photograph only. Text darkens to #1C3A2E to hold AA on a light image.
Never glass
· The balance surface or any amount · Transaction and activity rows · Inputs, and any primary button · Cards that carry the reward's cost
Rules
· One glass layer at a time — when a sheet or dialog opens, chrome drops to opaque so blurs never compound · Blur only ever 3 / 10 / 18 / 28 — no other values · Text on glass holds AA against the lightest backdrop possible · Keep the 1px edge: without it the layer's boundary disappears
Fallback 
@supports not (backdrop-filter: blur(1px)) {
  .glass-chrome  { background: #F5F7F8; }
  .glass-overlay { background: #FFFFFF; }
}
Opaque fallback everywhere blur is unsupported — the layout must not depend on translucency.
04

Mobile → desktop rules

≥ 0 · base Single column, bottom nav 16px margins. Primary action pinned in the thumb zone. Sheets, not modals. Everything reachable one-handed.
≥ 600 · wide phone / small tablet Two-up cards, 24px margins Content caps at 560px and centres. Lists gain a secondary column of metadata rather than stretching.
≥ 960 · desktop Bottom nav → left rail Same destinations, same order, same labels. Sheets become right-side panels. Row height drops 48→40px, type stays put.
≥ 1280 · owner console Detail beside list The extra width buys a persistent detail pane and more rows per screen — never larger type or more whitespace.
The rule that governs all four: width buys information, not size. Type scale, colour roles, radii and component anatomy are identical at every breakpoint — only column count, row density and nav position change.
