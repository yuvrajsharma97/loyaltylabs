Changed from the repo
Auth is reconciled, not reimagined. Sign-in keeps the customer / shop-owner toggle, the leading mail and lock icons, the shared show/hide control, and the Google button that only appears for customer accounts. Credential errors surface as the app's top-centre toast, not an inline banner. Admin sign-in is email and password only — no second factor exists in the code, so none is drawn. Verify-email is the link-landing page. Its four real states are all here — verifying, verified, already verified, and expired with the resend form. "Check your email" is a separate screen, because that's the sign-up success state. Phone moved last. Customer onboarding asked for a number before showing any value. Now it's interests → shops → optional contact, so the ask arrives after the payoff. Till code is framed as a blocker. It was a quiet step 3; it now says plainly that nobody can scan without it, and Continue stays disabled until four digits are in. Named progress. Anonymous bars became labelled steps, so people know what's left. Live previews. Earning rules and the first reward render as the customer will see them, in pounds. A completion screen for owners. The repo dropped owners straight onto the dashboard; a short checklist confirms what's set and what's outstanding.
Responsive rule These screens carry no data density to gain from width, so desktop keeps the same single 420–460px column, centred, with larger gutters. Width buys breathing room here, not extra columns — unlike the dashboards.
Next up Customer wallet, store directory, shop rewards, QR screen and account settings — then the till flow, owner settings and the admin tables.
