Grounded in the repo
Mobile nav is the shell's own hamburger. DashboardShell.jsx renders a floating glass bar with a hamburger and a dropdown holding the nav items plus the footer at mobile — so 390 gets that dropdown, not a bottom bar. Desktop keeps the left rail this project already uses. Six nav destinations — overview, rewards, till, transactions, disputes, settings — with the repo's own icons. Settings is one page, three panels, because Settings.jsx composes store info, loyalty program and till PINs together. The reward form is exactly the source's fields — title, optional description, type, a value input that only appears for the two discount types, and points required. Remove is a soft delete, and the confirmation says so; the pending-redemptions warning that follows it is kept. Both dispute tabs, with the transaction type, the customer's note, the date and your own note on resolved ones.
Changed, and why
Raw enum values became English. The ledger's filters and rows printed suspension_reversal and slug_manual straight from the API. Shop owners aren't reading an enum. Filters are chips, not two selects. On a phone a native select is two taps and a modal; the type filter is the main thing anyone touches here. One save bar for all three settings panels. Source gives each panel its own Save, so a rate change and a PIN change are two separate saves with no indication either is pending. One sticky bar, appearing only when something's dirty. Till codes are masked. They were printed in full on a screen an owner might have open at the counter; the last digit stays visible so you can tell rows apart. Disputes lead with the customer's words and carry the points at stake, so the queue can be triaged without opening anything.
